# 🛡️ Impeccable Coding & Engineering Guidelines

ยินดีต้อนรับเอเจนต์! นี่คือระเบียบและกฎเหล็กในการเขียนโค้ด การแก้บั๊ก และการออกแบบ UI ที่เป็นแนวปฏิบัติระดับสูงสุดสำหรับโปรเจกต์นี้

---

## 💻 1. แนวปฏิบัติในการเขียนโค้ด (Impeccable Coding Rules)

* **ความสะอาดและการอ่านง่าย (Clean Code):**
  * พยายามเขียนโค้ดให้สะอาด มีโครงสร้างแยกฟังก์ชันการทำงานอย่างชัดเจน (Single Responsibility)
  * ตั้งชื่อตัวแปร ฟังก์ชัน และคลาสให้เป็นภาษาอังกฤษแบบกึ่งอธิบายความหมายในตัว (Self-documenting)
* **การรักษาคอมเมนต์ดั้งเดิม (Preserving Comments):**
  * ห้ามลบคอมเมนต์ดั้งเดิมของโปรเจกต์ทิ้ง เว้นแต่จะระบุให้เขียนแทนที่
  * เขียนคอมเมนต์ใหม่ที่เป็นประโยชน์ช่วยอธิบายตรรกะในภาษาไทยเพื่อความเป็นมิตรต่อผู้พัฒนา
* **การทำงานย้อนหลัง (Backward Compatibility):**
  * ทุกการแก้ไขโมดูลหรือฟังก์ชันหลัก ให้คำนึงถึงจุดเรียกใช้งานดั้งเดิมเสมอ เพื่อหลีกเลี่ยงไม่ให้ส่วนอื่น ๆ ของระบบพัง

---

## 🔍 2. แนวปฏิบัติในการแก้บั๊กและการทดสอบ (Bug Fixing & Verification)

* **ความปลอดภัยของระบบดาต้าเบส (Database Integrity):**
  * ห้ามรันคำสั่ง SQL ที่ไม่มีการครอบด้วยตัวแปรป้องกัน SQL Injection
  * กรองข้อมูลขาเข้าผ่าน Middleware ด่านหน้า (เช่น `express-validator`) ทุกครั้งก่อนนำข้อมูลไปคิวรี
* **แนวทางการทดสอบแบบไม่มี Dependencies ภายนอก (Zero-dependency Tests):**
  * เมื่อเขียนสคริปต์สำหรับการตรวจสอบความถูกต้อง (Integration Tests) ให้หลีกเลี่ยงการใช้โมดูลเสริมภายนอก (เช่น `axios`) และเลือกใช้คำสั่งพื้นฐานอย่าง `fetch` ของ Node.js เพื่อให้รันได้ทันทีโดยไม่ต้องทำการดาวน์โหลดใด ๆ เพิ่มเติม
* **การดักจับข้อผิดพลาด (Robust Error Handling):**
  * ครอบคำสั่งเชื่อมโยงการทำงานหลักด้วยบล็อก `try-catch` เสมอ และหลีกเลี่ยงการปล่อยให้ระบบแครชแบบเงียบ

## 🎨 3. ความงามทางสุนทรียภาพและการออกแบบ UI (Premium UI & Styling Rules)

* **ยึดมั่นความงามระดับสูง (Premium Design Aesthetics):**
  * เลี่ยงการใช้สีแบน ๆ ดั้งเดิม (Plain RGB red/blue/green) ให้ใช้ชุดสี HSL tailored palette ที่มีความนุ่มนวลและทันสมัย
  * เลือกใช้สไตล์การออกแบบประเภท **Glassmorphism** และโทนสีมืดเรืองแสง (Glowing neon accents) ที่เข้าคู่กันอย่างลงตัว
* **โครงสร้างการยืดหยุ่นหน้าจอ (Responsive Flex layouts):**
  * ออกแบบ UI ให้รองรับสัดส่วนแสดงผลทั้งบนโทรศัพท์มือถือและหน้าจอเดสก์ท็อปขนาดใหญ่ (Mobile-first or Flex-grid)
  * ใช้ CSS Variables ในการจัดเก็บชุดสีและระยะเว้นขอบ (Margin/Padding) เพื่อความเป็นระเบียบเรียบร้อยของโค้ดสไตล์ชีท
* **การเคลื่อนไหวแบบละมุน (Micro-animations):**
  * เพิ่มเอฟเฟกต์การวางเมาส์ (Hover transitions) และการเคลื่อนไหวขนาดเล็กในหน้าต่างเมนู เพื่อสร้างความประทับใจเมื่อใช้งาน

## 🚀 4. วินัยการ Deploy และเวอร์ชัน (Deployment & Versioning Discipline)

* **ห้าม bump version เองโดยไม่ถาม**: ก่อน deploy ทุกครั้งต้องถามผู้ใช้ก่อนว่าต้องการ bump เลขเวอร์ชันไหม พร้อมแนะนำระดับที่เหมาะสม (patch/minor/major) และเหตุผล — ดูรายละเอียดที่ [[07_document/AI_Agent_Entry]] หมวด "กฎการตั้งเลขเวอร์ชัน"
* **ทดสอบหลัง deploy ทุกครั้ง**: อย่างน้อยต้องเช็ค endpoint หลัก (`/`, `/api/health`, endpoint ที่ต่อฐานข้อมูล, endpoint ที่ล็อกอิน) ว่าตอบสนองถูกต้องก่อนถือว่า deploy สำเร็จ — สถานะ "Build successful" ไม่ได้แปลว่าแอปทำงานถูกต้องจริง (พบว่า build ผ่านแต่หน้าเว็บ 404 หรือฐานข้อมูลต่อไม่ติดมาแล้วหลายรอบ)
* **บันทึกปัญหาที่เจอจริงระหว่าง deploy ไว้เสมอ**: ดู [[07_document/Deployment_Guide]] เป็นตัวอย่าง — ปัญหา infra/build config มักไม่ชัดเจนจน log บอกตรงๆ ต้องมีบันทึกไว้กันแก้ซ้ำ
